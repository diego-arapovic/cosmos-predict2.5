# world2action → Cosmos-Predict2.5: design decisions that could bite us

Concise register of choices made during the port that carry risk. Scores are subjective.
- **Likelihood** = chance it actually causes a problem (Low / Med / High).
- **Severity** = how bad if it does (Low = tunable/cosmetic, Med = degraded policy/retrain, High = broken/silent-wrong).

| # | Decision | Likelihood | Severity | Notes / mitigation |
|---|----------|:---------:|:--------:|--------------------|
| 1 | **Rectified-flow noising replaces mimic-video's additive EDM noising.** `xt = σ·ε+(1−σ)·x0`; net gets discrete timestep `σ·1000`. | Low | Med | Grounded in the real `Video2WorldModelRectifiedFlow.forward` (timesteps∈[0,1000], `timestep_scale=0.001` confirms the net wants [0,1000]). If subtly wrong, features come from a wrong noise level → worse but trainable (decoder is conditioned on σ). Backbone smoke ran finite. |
| 2 | **σ sampled `logitnormal` + `shift=5`** (the finetune's training distribution) → biased toward **high noise** (smoke drew σ=0.93). | Med | Low-Med | This is now understood as roughly **correct**: at deployment the future frames are pure noise (**σ=1.0**, no future available), so a high-σ tap matches deploy (the backbone *predicts* the future rather than copying a given one). Eval must therefore be at σ≈1.0, not 0.5 (fixed: `val_action_sigmas=(0.5,1.0)`). Residual risk: a single high-σ forward is a crude one-step future prediction — if features are too weak there, deploy needs the multi-step `generate_video` tap (#12). Cheap ablation if learning stalls (#27). |
| 3 | **Backbone built piecemeal, NOT from the Hydra experiment config.** We pin net overrides (rope ratios, projection, `timestep_scale`, `use_wan_fp32_strategy`), VAE `temporal_window=16`, conditioner. | Low | Med | A forward-affecting default in `cosmos_v1_2B`/model config we didn't replicate would shift features. Strong guard: checkpoint loads **689/689, 0 mismatch** (architecture matches); all known forward-affecting knobs pinned from `..._RECTIFIED_FLOW`. Residual risk = an unpinned non-param default. |
| 4 | **Conditioner text/video-condition dropout forced to 0** for deterministic extraction (finetune trained text-dropout 0.2). | Low | Low | Correct for using a frozen extractor; matches eval (real instruction, no dropout). |
| 5 | **`fps=16` hardcoded.** | Low | Low | `rope_enable_fps_modulation=False` in the finetune → fps does not modulate anything. Moot unless that flag changes. |
| 6 | **Frozen 2B backbone is NOT FSDP-sharded** (full copy per GPU, forward-only). | Low | Low | Fine on 96 GB (bf16 2B ≈ 4 GB). If we move to smaller GPUs or shard, `FrozenVideoBackbone` needs FSDP support added. |
| 7 | **Native tap runs all 28 DiT blocks** (no early-exit at layer 19). | High (it does) | Low | ~28% extra backbone compute/step vs mimic-video's early-exit. Frozen + features cacheable → precompute to erase it. Pure throughput. |
| 8 | **Full-res throughput on 1 GPU.** 720p → ~3,600 patch tokens/frame × 24 = ~86k tokens; the per-step **frozen-backbone forward** (28 blocks over 86k tokens) dominates each training step, and the node has **1 GPU** (the finetune used 8 GPUs + CP=2). | High | Med | Memory is fine (96 GB + flash-attn); the issue is **wall-clock per step** (~10 s/sample/GPU, measured). **Feature caching is INFEASIBLE** (corrects the earlier "cacheable" premise): the tap is ≈86k tokens × 2048 ≈ **350 MB/chunk** × ~83k chunks = PBs. So the backbone forward is unavoidable per step. Levers: **more GPUs** (≈linear; one 83k-chunk epoch ≈ 1.2 days on 8 GPUs), early-exit at the tap layer (~30%, #7), or fewer action-video latent frames (changes feature content). Validate per-step time on the smoke before a long run. |
| 9 | **Data contract (step 2, not built yet):** YAMS teleop must produce `obs/workspace_rgb`, `action/workspace_rgb` (RGB in [-1,1]) whose concatenated length → `state_t=24` latent (93 px frames), and cached Reason1 `obs/language_embedding` shaped `(B, L, 100352)`. | Med | Med | These keys are the backbone's API. Wrong frame counts / un-normalized RGB / wrong embedding dim will fail at encode or the net. Pin this contract when building `data/`. |
| 10 | **Language enters ONLY via the frozen backbone's features** (decoder gets no separate language input). | Low | Med | Verified: `World2ActionDIT.forward` takes only video `crossattn_emb`. If the backbone underweights text, the policy is weakly language-conditioned — inherent to the world2action method, not a port bug. |
| 11 | **EMA-fused checkpoint is the frozen backbone** (`model_ema_bf16_fused.pt`). | Low | Low | EMA = the intended "final" finetuned weights; LoRA pre-merged. **RESOLVED:** both the fused path *and* the base+LoRA-merge fallback PASS the backbone smoke on-node. |
| 12 | **In-training eval wired; `generate_video` (genvid) sweep still deferred.** `model.validation_step` now computes held-out `val/loss` + the **sampled-action MSE** vs the demo (raw joint space, at `config.val_action_sigmas`) + a hold-last baseline, logged to W&B by `World2ActionWandb`. The genvid (backbone-sampled-video) sweep needs a backbone sampler → still deferred to real-rollout deployment. | n/a | n/a | Not a risk — the unbiased "is it learning" signal is now in place; genvid is extra. |
| 22 | **The eval/sampler path (`validation_step`→`predict`→`World2ActionPipeline.__call__`).** | Low (resolved) | Low | **RESOLVED — gate PASSED on the node (2026-06-07):** the tiny `yams_medium` override run forced iter-0 + periodic validation, the sampled-action eval, W&B (offline), `train()/eval()` cycling and a DCP save → S3, no crashes. Same code path as deployment inference, so it also de-risks step 3. It surfaced risk #25 (eval metric only discriminates when the val set moves). |
| 24 | **Training dataloader was NOT shuffling** (`shuffle` unset → `False`; trainer injects no sampler). | Low (resolved) | Med | **RESOLVED:** `_dataloader` now passes `shuffle=True` for train (and val). Was harmless for the 3–4-iter smoke/gate but for a real run it meant SGD saw chunks in episode order (one episode at a time → correlated batches, poor mixing, misleading loss curve). Multi-GPU still needs a `DistributedSampler` (#23). |
| 27 | **It IS learning — earlier "stuck at the mean floor" was a miscalculation (corrected).** I claimed the floor was ~15 using **within-chunk** `Var_inst≈0.5`; the do-nothing/predict-zero loss is actually `(1+E[x0²])·10 ≈ 18–20` (E[x0²]≈1 for unit-normalized actions, NOT the within-chunk variance). At step 720 `train/loss` reached **11.8 ≪ 18–20** ⇒ learning. **The completed 1500-step run confirms it strongly:** train/loss 25→**7**, **val/loss 27→5** (no overfit — val ≤ train; shuffle fix worked), action_mse@σ0.5 0.34→**0.07**, action_nmse 1.63→**0.39** (≪1 ⇒ well past predict-the-mean), echo>0 (not collapsed). Curves still steep at 1500 ⇒ not converged, needs more steps. **Train/loss is still a weak metric; judge by eval (prefer nmse + σ=1.0).** | Low (resolved) | — | Lesson: don't quote a floor from `Var_inst` (within-chunk) — it's not `E[x0²]`. Capability is proven; the remaining gap to a deployable policy is (a) steps and (b) an honest σ=1.0 eval — see #28/#2. NB the σ=0.5 action_mse **leaks half the GT future** ⇒ optimistic; `skill_ratio` 1.75 is harsh because tiny raw motions make "do nothing" a strong baseline (nmse is the cleaner learning signal). |
| 28 | **Global batch differs from mimic-video, but batch 1 demonstrably learns (claim tempered).** mimic-video trains at global batch 128–256; we ran **global batch 1** — and the completed 1500-step run learned cleanly (val/loss 27→5, action_nmse 1.63→0.39, no overfit). So batch 1 is **not** a blocker (I earlier over-claimed it was "THE lever to escape the mean floor" — there was no stall). lr=1e-4 ✓, loss_scale=10 ✓, num_denoising_steps=10 ✓, obs_dropout=0.2 ✓, sampler+`denoise` byte-identical ✓. | Low | Low | Bigger effective batch is an **optional** convergence-smoother (grads were noisy, 33–1168), not a fix. For the full run aim for a **modest** eff-batch (~8–32, cheap on a few GPUs) and **prioritise steps/samples over batch** — throughput is the real constraint (720p/86k tokens ≈ ~10–20× mimic-video's 480p/19k; chasing batch 128 is not worth it). |
| 29 | **Decoder timestep distribution deviated (fixed).** Our `SchedulerConfig.alpha` was **1.5** (Beta(1.5,1) → decoder action-noise `t` biased high); mimic-video uses **alpha=1.0** (uniform `t`). Over-weighting high `t` under-trains the low-noise regime where fine action detail is learned. | Low (resolved) | Low | Fixed to `alpha=1.0` to match mimic-video. (Distinct from the *video* σ — see #2/#30.) |
| 30 | **genvid (generate-the-future) eval/deploy path not ported.** mimic-video's deploy + the unbiased eval *generates* the future video (full denoise, tap features along the schedule), `validation_step` lines 450–491. We do a single-forward feature tap at one σ. | Med | Med | For TRAINING both use single-forward σ-conditioned taps (we match). But the real policy/eval is genvid; single-forward at σ=1.0 is a crude one-step proxy (leakage-free but weak). Port genvid before trusting absolute deploy numbers (#12). |
| 26 | **Run identity / resume.** `train.sh` keys the job dir + W&B id + S3 checkpoint path on `RUN_NAME` (timestamped per launch by default). Earlier the name was fixed (`=$EXP`), so a second launch silently **reused the prior W&B run id and resumed the prior checkpoint** (e.g. a "fresh" yams_medium continued the gate's iter-4 weights → one merged 0→660 W&B run). | Low (resolved) | Low | **RESOLVED:** timestamped default → each launch is its own run (fresh W&B id + checkpoint dir). Resume is now explicit: relaunch with the **same** stable `RUN_NAME` (pulls checkpoint + `wandb_id.txt` from S3). Residual: (a) reusing a stable `RUN_NAME` that already has an S3 checkpoint silently resumes it (intended, but know it); (b) timestamped job dirs accumulate on scratch (each has a W&B offline dir + console.log) — periodically clean `$IMAGINAIRE_OUTPUT_ROOT/world2action/yams/`. |
| 25 | **The action-MSE eval only distinguishes a real policy from "do nothing" when the val set actually moves** (`val/baseline_hold_last_mse` > 0). With absolute-joint BC the decoder is fed the current pose and the target is dominated by "hold it", so it can collapse to **proprio-echo, ignoring the video/language features** — and raw MSE can't see that if the demo barely moves. | Med | Med | Mitigated, not eliminated: (a) representative val set (8 shuffled episodes) so baseline>0; (b) `val/echo_mse` + `val/skill_ratio` + normalized `val/action_nmse_mean` expose collapse; (c) **watch `baseline`/`echo` on W&B** — if baseline≈0 the eval is uninformative. If collapse is confirmed on a real run, mitigations: predict deltas/relative motion, down-weight/drop proprio conditioning, or weight the loss toward moving joints. Language-sensitivity probe (multi-task) is the definitive check, deferred. |
| 23 | **No `DistributedSampler` on the train/val dataloaders** (`sampler=None`; the trainer's `validate()`/train loop iterate the loader directly — no auto-sharding). | Low (1 GPU) | Med (multi-GPU) | Harmless on 1 GPU (current). On multi-GPU **DDP every rank would see the same data** (redundant, effectively smaller epoch) and the val action-MSE would be measured on identical samples per rank. Pre-existing (affects train too); fix when scaling out — add a `DistributedSampler` (or shard via `parallel_state` rank) in the dataloader factory. The model's DP-reductions are already rank-symmetric, so enabling a sampler is the only change needed. |
| 13 | **`EMAConfig` is our own 3-field class** (`enabled`/`rate`/`iteration_shift`), not `_src.imaginaire.config.EMAConfig` (`enabled`/`beta`). | Low | Med | Necessary: `pipeline.py`/`model.py` read `rate`+`iteration_shift`. Matches the predict2 `EMAConfig`. If EMA is enabled and the trainer expects imaginaire's field names, reconcile in the config step. Smoke runs EMA-disabled. |
| 14 | **Grad clip = stdlib `torch.nn.utils.clip_grad_norm_`** (not mimic-video's custom `torch_future` wrapper). | Low | Low | Matches what 2.5's own `Text2WorldModelRectifiedFlow` uses under FSDP2/DTensor. Only relevant once FSDP training runs. |
| 15 | **720p video prep recipe** in `process_recordings.py` = center-crop-to-16:9 + INTER_AREA resize to 1280×720. | Med | Med | The frozen backbone's features are only in-distribution if this matches how the **finetune** prepped its 720p video. center-crop+resize is the cosmos-augmentor convention, but unverified against the actual finetune. If features look degraded, this is the first knob (squash vs crop vs different crop box). Confirm against the finetune's data pipeline. |
| 16 | **Reason1 `full_concat` embedding is 100352-d ≈ 102 MB/episode** (vs T5's 1 MB). | Low (mitigated) | High | Storing it per-episode in zarr + reading per `__getitem__` would crater dataloader throughput. **Mitigated:** `Reason1EmbeddingLookup` reads a single `reason1_embeddings.pt` keyed by instruction, `mmap`'d (shared across workers); the dataset reads only the tiny `language_instruction` string. `language_smoke.py` PASS. |
| 17 | **2.5 `ImaginaireTrainer` calls `on_train_start(memory_format)` — 1 arg, no dataset stats** (mimic-video's trainer passed `dataset_stats`/`stats_id` via introspection). | Low | Med | We made `on_train_start` 1-arg + load **precomputed** stats from `config.normalizer_stats_path` (`precompute_stats.py`) — keeps the overlay free of stock-trainer edits, and offline stats beat a full-dataset pass at every train start. Caveat: the stats file must be regenerated when the data/policy_io changes (its `stats_id` encodes the config); if `normalizer_stats_path` is unset, actions train **unnormalized** (a warning is logged — don't ignore it). |
| 18 | **The trainer does not call `model.clip_grad_norm_`** — grad clipping is a `callbacks.grad_clip` entry in the experiment config. | Med | Low | If the experiment omits the grad-clip callback, no clipping happens (the finetune used `clip_norm` 0.1–1.0). Wire `callbacks.grad_clip` in the `yams` experiment. |
| 21 | **The `basic` callbacks assume a video2world model** — `compile_tokenizer` does `model.tokenizer`. | Low (handled) | Low | `World2ActionModel` now exposes `.tokenizer` → the backbone VAE (so `compile_tokenizer` works + compiles the VAE encode = a perf win). Other `.tokenizer`/EMA-sampling callbacks (`val_loss_computation`, `every_n_draw_sample`) are NOT in `basic` and validation is off, so they don't run. If a future callback assumes more video2world structure, override `/callbacks` (group package `trainer.callbacks`) to a minimal set. The trainer loop + callbacks + DDP + DCP are first exercised by `commands/train.sh` (not the config smoke). |
| 20 | **Processed zarr is large: ~295 GB** (workspace-only, 720p — decoded uint8 frames ≫ the ~tens-of-GB h264 raw). | Low (resolved) | Low | **RESOLVED:** `prepare_data.sh` now **re-derives the zarr from raw** (~3 min CPU) and caches to S3 only the small Reason1 cache (+stats) — ~200× less S3/transfer. (Delete the old `s3://…/world2action/processed/` prefix.) Open (curation, user keeps for now): a few long "play data" episodes dominate — one is **475 s / 14,104 frames ≈ 9% of all chunks**. |
| 19 | **Elastic node:** currently 1× RTX PRO 6000 (96 GB); user can add GPUs + size disk on demand. Scratch `/opt/dlami/nvme` (1.7 TB NVMe) is **EPHEMERAL** (wiped on stop/terminate). | Med (data loss if ignored) | High | **S3 is the source of truth; scratch is the fast working copy.** `prepare_data.sh` caches processed data to S3 (never reprocess); `train.sh` (next) resumes from + syncs checkpoints to S3 (never lose a run). Config is GPU-count-agnostic (DDP, per-rank batch; `torchrun --nproc_per_node=N`; FSDP/CP future switches). `CAMERAS=workspace` for the processed cache (training-only); raw S3 keeps all cams for future multi-view. |
